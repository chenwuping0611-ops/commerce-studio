Pear AI production release manifest
Created: 2026-09-08 12:20:00 +08:00
Source state: current working tree based on baseline a9f3f3b

This release contains the current production code, templates, static assets,
database migrations, deployment scripts, and built-in Skill files. It is
intended to update an existing production checkout without importing local
configuration or local business data.

Included:
- app.py, gunicorn.conf.py, start.sh, README.md, LICENSE
- applications/
- migrations/ (Python migration files only)
- templates/
- static/ (excluding static/upload/)
- requirement/
- deploy/
- .flaskenv.example and safe project metadata

Excluded:
- .flaskenv and all API keys, passwords, and local connection settings
- .venv/, .git/, __pycache__/, *.pyc, logs/, tmp/, instance/
- test/, docs/, agent.md, local databases, local demo data
- static/upload/ and all persistent user-uploaded files
- docker-compose.yml and other local-only development assets

Key changes included:
- Built-in Skill synchronization, including White_Background_Image_Refinement_Skill.md
- Batch prompt style management and page-selected style precedence
- Batch image processing as independent per-version image tasks
- Product-center-only reference images for batch image generation
- Product image URL snapshots for batch prompt histories, with legacy fallback
- Interface AI image prompt limit of 32000 characters
- White-background image workflow and related history/binding support
- Batch prompt and Amazon AI custom-name migrations
- Current provider, model, task-history, product-asset, and UI updates
- New image batch prompt histories require a selected Product Center record

Online data policy:
- Keep the online .flaskenv, .venv, database, GoFastDFS files, provider API
  keys, Skill records, products, and execution history.
- Run flask db upgrade before restarting.
- Run flask sync-skills after migration so changed built-in Skill files are
  uploaded to the online GoFastDFS and mapped in the online database.
- Never run flask init --fresh and never copy local database or history files.

The deploy/update_online.sh script validates the archive, preserves the online
.flaskenv/.venv/runtime directories, backs up the previous application, applies
migrations, synchronizes built-in Skills, and restarts the root-owned service.
